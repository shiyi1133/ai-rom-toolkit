平台与工具选择

指南审阅日期：2026-10-16。扩容流程与案例另见 LOCALIZATION_WORKFLOW.txt。

GBA
CPU 为 ARM7TDMI（ARMv4T），既有 ARM 又有 Thumb，按具体函数状态分析。
主 ROM 映射常见 0x08000000；对于该主映射，文件偏移 = 地址 - 0x08000000。
镜像区、运行时 RAM 复制代码、overlay 和游戏自定义映射要单独确认，不能无条件套用。
使用 arm-none-eabi-as/gcc/ld/objcopy/objdump。GBA 代码注入显式指定 -mcpu=arm7tdmi。
Thumb C 片段可采用 -mthumb -mthumb-interwork -mfloat-abi=soft -ffreestanding -fno-builtin；还需核对项目 ABI 和链接地址。
Arm 官方工具链不替代 devkitPro/libgba。完全源码构建保持原项目的 SDK、链接脚本和版本。
反汇编例子：arm-none-eabi-objdump -D -b binary -m arm -M force-thumb --adjust-vma=0x08000000 fragment.bin
只对已知 Thumb 片段使用 force-thumb；数据表不能直接认成指令。

GBA 字库与显存
原文码值是游戏自己的编码；u16 字形编号不等于 UTF-16，字符位宽、控制码边界和合法范围须由实际读字函数确认。
分别记录 ROM 中的字库容量、可编码字形数、运行时缓冲、显存同时缓存的字形数；动态加载时无需把整套中文字库常驻显存。
图块模式下 BG 图块/地图使用 0x06000000..0x0600FFFF，OBJ 图块使用 0x06010000..0x06017FFF。
0x06014000..0x06017FFF 属于 OBJ 区；不能把它直接当成 BG 对话字库。其它显示模式要按自身映射另查。
确认 4bpp/8bpp、调色板、字模顺序、字宽/步进、字库选择表、动态缓存和地图的引用，再决定扩字方案。
优先复用已证明的原生缓存/绘字机制；先统计实际译文用字，确需更多字形时再评估集中字库、搬移或读取入口改动。
不要把原 ROM 的 512 槽、几个填充空洞或某个样本的可用字数当成 GBA 的硬件汉字上限。

GB / GBC
CPU 为 SM83，RGBDS 用于汇编/链接，不能用 ARM 或普通 Z80 指令替代。
CPU 地址 0x0000..0x3FFF 为 ROM0，0x4000..0x7FFF 为切换窗口；MBC1 等存在模式/映射例外。
物理 bank 与文件偏移关系：bank 0 的 ROM0 偏移就是地址；bank>=1 的 ROMX 偏移为 bank*0x4000+(address-0x4000)。
MBC 寄存器值不必等于物理 bank；结合 MBC 类型和模式证明实际 bank。
工具：python tools\romkit.py bank-offset --bank 3 --address 0x4567
同一个 CPU 地址可能指向不同 bank，补丁/断点/文本记录必须附 bank。
指针可能是银行内地址，也可能另带 bank 字节或专用编码，不能把 u16 指针一律当文件偏移。
GB/GBC 字形可能为 1bpp/2bpp 图块，需确认实际布局和字形索引。
GBC 另有 VRAM/WRAM bank、颜色属性与调色板；新增中文字库还要检查 bank 和显示时序。
RGBGFX 可转换兼容图片/图块，不能自动识别每个游戏自定义压缩资源。
rgbfix 会更改头部、校验及可能填充文件。不要对原始 ROM 或未经审核的补丁输出盲目调用。

GB / GBC 扩字与缓存
采用扩展码、带前缀字形编号或逐段局部字表时，先证明读字程序、原控制码和变量的边界；不能统一按双字节文本处理所有游戏。
ROM 字库的总字数与显存图块槽位分别预算。记录缓存使用的图块编号、VRAM bank、属性和地图；保护场景图形、当前页及待显示文字。
跨 ROM bank 取字要检查 MBC 状态保存/恢复和中断或其它消费者；ROM 扩容还需核对 mapper 可达范围及输出头部/校验。
普通 DMG、CGB、SGB 等实际交付模式分别记录；SGB 预设着色不等于 CGB 运行，也不能用一种模式代替另一种模式的测试。

通用汉化重点
保留文本控制码、终止符、分支、变量和音频；记录空间与字形预算。
确认资源消费者与引用范围，先小样验证再批量写入；字面指针扫描没有找到的部分仍需检查索引、相对指针、压缩、脚本和运行时计算路径。
字库、文本搬移与注入代码共用一份占用区登记并由项目构建器检查冲突，规则见 LOCALIZATION_WORKFLOW.txt。
正文能显示中文、原生取名能输入中文、正常保存后新进程能读回，是三个需要分别证明的结果。
源码构建、静态反汇编、模拟器脚本、人工操作和真机测试各自证明不同范围。
