游戏改版工作流（GB / GBC / GBA）
审阅日期：2026-10-16

用于已授权的数值、系统机制、技能、道具、菜单、地图/事件改版，也用于已有功能的移植和组合。
它与汉化指南并列；新增汉字/文本时再使用 LOCALIZATION_WORKFLOW.txt。工具准备不产生游戏任务授权。

一、按目的选择提示词
prompts/04_MOD_GAME.txt：明确功能规则后端到端实现、必要验收与交付。
prompts/05_INVESTIGATE_MECHANIC.txt：未知机制/金手指/旧补丁只读调查，不授权写入。
prompts/06_PORT_OR_COMBINE_MODS.txt：已有功能移植或组合，绑定来源与目标身份。
先按宿主系统使用 Windows 或 Linux 的 00_BOOTSTRAP 初始化环境，已有项目按实际状态续接。

二、先定义功能，再找位置
用 templates/MOD_SPEC_TEMPLATE.txt 指定触发者、条件、输入单位/范围、原行为、目标规则、成功结果、副作用、失败分支和持久化。
例如“提高等级上限”不仅是一个比较常量：还可能涉及经验表长、索引、溢出、UI 位数、升级奖励、菜单和保存读回。
先查现行基底内建哪些修复/改版，避免将已内建功能重复打入；来源/地区/修订不同就重新识别，不删除 SHA 或前像断言。
没有项目规格就不能把旧攻略里的一句目标当完整功能定义；必要信息未明时只继续独立的只读调查。

三、从线索走到证据
关键词、常量、金手指、函数名、反编译伪代码与补丁差异只产生候选，不直接给出修改字节。
链条应能解释：输入来源 -> 写入/生产者 -> 字段/表 -> 条件分支 -> 调用/返回 -> 消费者 -> 玩家可观察效果。
确认字段宽度、大小端、符号性、索引步长/界限、哨兵、舍入/溢出、生命周期及保存载入是否重建该字段。
RAM 金手指是运行时效果线索；要识别代码格式、写入条件和周期，再找对应的 ROM 初始化/计算/消费路径，不直接减 ROM 基址换算。
历史伪代码须标其基底与静态来源，回到当前输入实读字节、函数状态与调用关系；缺反编译不等于不能从小范围反汇编继续调查。
扫描先限定系统/范围，最多展示约 20 个候选和局部字节；收窄后再跟进，避免全 ROM 无差别输出。

证据标签
hypothesis：线索/假设；inferred：证据支持但尚有替代解释。
confirmed/static：当前字节、结构/交叉引用确认，未证明运行效果。
dynamically verified：明确目标 ROM/SAV/环境/路径下实际观察到结果。
user accepted：用户给出的有限验收范围；不是当前 AI 复测。
not_run / not_reproduced / blocked：未执行、未复现、真实阻碍，分别记录。
这与功能状态 research/candidate/tested-scoped/released 是两列，不能相互代替。

四、平台分别分析
GBA
- ARM7TDMI/ARMv4T，按函数确定 ARM/Thumb。Thumb 入口指针低位表示状态，不是文件中可直接写入的奇数代码位置。
- 只在已确认主 ROM 映射使用 address-0x08000000；镜像、RAM 复制代码、DMA、overlay 要追实际来源。RAM 地址不能这么换算。
- 数据表不能强制当指令；单字节补丁也须恢复完整半字/字指令再审核。
- Hook 需确认覆盖的完整指令、入口/返回点、分支可达性/跳板、PC 相对加载和字面量池。
- 调用替换先检查参数、返回值及其消费者、寄存器/标志、LR/栈、对齐和副作用；同样长度、同指令集不代表语义兼容。
- 使用显式 ARM7TDMI 汇编/编译选项，保留链接地址、map 和源码；旧 SDK 完整工程沿用其声明环境。
GB / GBC
- CPU 为 SM83，不能把 ARM/Thumb 或通用 Z80 代码套进来。
- 物理 bank、MBC 映射、CPU 地址和文件偏移分别登记；相同 CPU 地址可能对应不同 ROM 内容。
- 跨 bank 调用/数据读取须证实 bank 保存恢复、中断/重入、寄存器/标志与栈约定；切换 bank 后当前代码是否仍可达也需确认。
- GBC WRAM/VRAM bank 与颜色属性、DMG/CGB/SGB 实际交付模式分别记录；没有所需模式就不凭截图冒认通过。
- ROM 扩容前查 mapper/头部和可达上限，不将修改文件大小当扩容完成。

五、管理注入、数据与补丁组合
代码、表、字库、文本和保留区共用 OCCUPANCY_TEMPLATE.tsv 或现有等价登记，ROM 区间统一为文件偏移 [start,end_exclusive)。
RAM/VRAM 另记生命周期、场景/中断使用期；不能只按 ROM 写入区判断冲突。
填充字节、零字面引用只是候选空闲区。读表索引、压缩块、DMA 与运行时计算也会占用。
项目构建器在写入前汇总全部分配与写入，检查所有权、重叠、边界、对齐、引用/分支可达和每个前像。
两个补丁不重叠，仍可能改同一字段、函数调用次序、返回约定或保存格式；需要受影响交互用例。
组合从同一确切基底生成一份最终计划；不要连续应用只接受原基底的单项补丁。
显式阶段链需要每段输入/输出 SHA、依赖和前像，最后仍验证最终产物；共享写入以合成源码解决，不能后写覆盖或静默丢功能。
romkit.py patch 只做等长定点写入的身份/前像/重叠/边界/输出保护。它不汇编 Hook、不重定位、不扩 ROM、不自动证明统一占用或组合语义。

六、迁移已有改版
分别冻结来源与目标，建立每项功能的语义、来源位置、目标候选、当前字节和证据等级映射。
固定地址差、字节相似、同名函数均不足以证明跨地区/修订可移植；在目标重新追调用者、参数/字段、分支、消费者和保存。
有源码优先重新链接/构建；仅有成品二进制时先区分头部/填充/压缩变化与功能差异，资料缺失如实记录，不冒称完整源码。
保留目标原有修复/玩法；不把来源所有差异盲目覆盖目标。来源的动态验收不继承为目标版本通过。

七、调试与必要验收
先写可观察现象与最短步骤，再只改变一个条件：基底与单项、单项与组合、边界前/中/后、保存前与新进程读回。
从输入层、生成差异、启动、功能入口、效果/副作用、边界、相邻回归到持久化逐层判断；启动失败时不先把原因归给某个未执行存档字段。
不强制每个功能重跑每一层；只做受当前变化影响且能区分问题的检查，沿用有身份和范围依据的未受影响证据。
同一目标功能既查预期结果，也查副作用/失败分支：如复活还应查物品是否只消耗一次、状态是否完整、无条件时是否回原流程。
用 MOD_TEST_MATRIX.tsv 记录明确目标 SHA、组合参数、环境、起点、输入、预期/实际与证据；脚本改 RAM 只作诊断，不能替代正常玩家入口。
保存/读档/字段受影响时，在隔离 SAV 中游戏内正常保存，关闭本任务旧进程，用新进程实际加载普通 SAV；保护玩家原档。
新/旧 SAV 兼容、即时状态兼容和真机分别报告。工具版本探测、GDB 连接、截图与无崩溃都不代表功能通过。
ROM 身份不符、覆盖区/返回路径/存档格式未知时停止对应写入，记清阻碍；继续其它不依赖缺失证据的已授权工作。

八、可复核交付
冻结参数/组合/目标 SHA 后，将最终源码包解压到独立空目录，使用声明依赖和确切基底重新构建；核同一目标完整 SHA。
对实际交付每种 IPS/BPS 等补丁独立回补并比对完整目标；工具包目前不内置 IPS/BPS 生成器，项目需声明采用的工具与版本。
交付包含改版规格、源码、构建脚本/依赖/许可、参数、占用登记、精确基底/目标身份、测试与未测范围、回退方式。
不将原/目标 ROM、SAV/state、BIOS、令牌和未经整理的私有反编译资料混进公开源码。公开上传范围依用户指令，模板不产生发布授权。
保留旧版本。研究候选、局部实测版、正式发布分别标记；未测功能和失败不能因“赶进度”消失。

来源边界
本流程参考作者提供的 SHARE 中 EVIDENCE_BOUNDARY、DEBUG_THINKING_GUIDE、analysis/DISCOVERY_GUIDE、analysis/tracing_cases、docs/code_audits/INJECTION_OWNERSHIP 等方法资料，并结合本工具包的跨平台与保护机制重新整理。
只提炼证据分层、调用/数据流、注入所有权、最小对照与组合风险。没有迁入 SHARE ROM、存档、旧游戏哈希/补丁地址、商业反编译语料或定制二进制。
SHARE 的历史 released/静态构建记录不等于本工具包已重新实测其改版功能；GB/GBC 的 bank/SM83 规则另按 PLATFORM_GUIDE 核查。
