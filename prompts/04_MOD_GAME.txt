1. 对齐范围、身份和工具。
阅读工具包 AGENTS.md、docs/MODDING_WORKFLOW.txt、docs/PLATFORM_GUIDE.txt，以及项目 project.json/当前回执/占用登记。
按执行主体选择 Windows python.cmd/.exe 或 Linux python.sh/ELF，不混用运行结论。环境缺项按对应 00_BOOTSTRAP 提示词准备，不为每个功能重复初始化。
身份命令：Windows .\python.cmd tools\romkit.py identity "<ROM>"；Linux bash python.sh tools/romkit.py identity "<ROM>"。
记录大小、SHA-256、CRC32/MD5、版本、内建补丁、存档身份和归属；输入不符先查原因，不改校验常量或强套旧定义。保持暂停项目暂停。

2. 把需求写成可观察的规则。
用 templates/MOD_SPEC_TEMPLATE.txt 记录触发者、输入、条件、公式/单位、成功/失败结果、副作用、持久化与验收步骤。
只缺会改变功能定义的必要信息才问我；已明确范围内的可逆调查/实现继续执行。
先建立基底的相关行为对照。找不到正常玩家入口/复现时如实记录，不用内存强改冒称入口通过。

3. 先证明机制，再改字节。
关键词、数值、金手指和旧伪代码仅产生候选；先追写入者、读取者、调用者、分支条件、返回值消费者和副作用。
确认字段位宽/符号性、字节序、记录步长、索引/哨兵、RAM 生命周期与 ROM 表来源。金手指是 RAM 效果线索，不能把 RAM 地址减 ROM 基址作文件偏移。
对等级/数量上限改动，核查生产、计算、比较、表长、UI、菜单、保存/读回等受影响消费者，不只改一个 cmp 或显示位数。
用 hypothesis / inferred / confirmed/static / dynamically verified / user accepted / not_run 标明每条证据。历史 ROM 上的测试不自动继承到当前基底。

4. 按平台实现最小可审阅改动。
GBA：确认 ARM7TDMI/ARMv4T、ARM/Thumb 状态、整条指令、Hook 覆盖长度、BL/BX、字面量、分支范围/跳板、r0-r3 参数/返回、被调用者约定、CPSR、LR/栈、对齐与返回原路径。必要时写汇编/链接源码，不手猜跳转字节。
GB/GBC：使用 SM83；记录 MBC/物理 bank/CPU 地址/文件偏移，跨 bank 调用须保留并恢复映射，检查寄存器/标志、栈、中断与 bank 冲突；不能套 ARM Hook 模板。
统一登记 ROM 代码/数据/字库/文本与预留区；RAM/VRAM 生命周期另列。空白字节不等于可注入区。
每个写入锁定基底及 before_hex，生成全新输出。romkit.py patch 只适合等长定点写入，不能代替汇编/重定位/扩容构建器，也不证明语义。
保留源文件、工具版本、参数、链接 map、计划与依赖次序。功能组合先合成计划，再从确切基底一次构建；不连续套只接受原基底的补丁。

5. 做受影响的必要验收。
静态检查包括指令、分支/表/引用、区域冲突、输出差异和基底不变；随后实际执行目标正常路径、适用边界、失败分支与相邻回归。
持久状态/存档受影响时，游戏内正常保存，完全关闭本任务旧模拟器进程，新进程实际读回隔离普通 SAV；旧 SAV 兼容和即时状态兼容分别报告。未经确认的存档布局先研究，不直接升级覆盖玩家档。
组合交付须核最终组合相关交互；单项通过/无地址重叠不等于组合通过。不重复未受影响的已通过检查，不默认完整通关。
用 templates/MOD_TEST_MATRIX.tsv 留具体 ROM 哈希、输入/步骤、预期/实际、观察证据和未测项。脚本直改 RAM 的诊断结果单列。
